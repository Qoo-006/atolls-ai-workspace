# paths: の付け方の例

`.claude/rules/` の中のMarkdownは、先頭に `paths:` がなければ毎回読み込まれる。
`paths:` を付けると、Claudeがそのパターンに合うファイルを読む・書く・編集するときだけ読み込まれる。

## 書き方（ファイルの先頭に置く）

```markdown
---
paths:
  - "scripts/deploy/**"
  - "docs/release-notes/*.md"
  - ".claude/rules/deploy.md"
---

# 公開作業のルール

- 本番に出す前に、テストの結果を報告に貼る
- リリースノートには、使う人が触る変更だけを書く
```

## パターンの例

| パターン | 合うもの |
|---|---|
| `**/*.py` | どこにあってもPythonのファイル |
| `scripts/deploy/**` | scripts/deploy/ の下の全部 |
| `*.md` | プロジェクト直下のMarkdown |
| `src/**/*.{ts,tsx}` | src/ の下の .ts と .tsx |

## 付けるときに気をつけること

- 例の3つ目のように、ルールのファイル自身もパターンに入れておくと、ルールを直すときに中身が読み込まれる
- 読み込まれるきっかけは、合うファイルを読む・書く・編集すること。合うファイルを開かずに、コマンドを実行するだけ・Webを調べるだけの作業では読み込まれない
- そのため、CLAUDE.md に「作業」と「読むルールのファイル」の対応表を残しておく（CLAUDE.md追記例.md）
- `---` の間がYAMLとして読めないと、paths: は無視されて毎回読み込まれる。`claude --debug` で読み込みの誤りを確かめられる
- 付けたあと、新しい会話で `/context` を開き、そのルールが起動時の一覧から外れたことを確かめる
