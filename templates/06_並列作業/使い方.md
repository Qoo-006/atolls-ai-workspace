# 並列作業キットの使い方

対応する記事：「AIの並行作業をworktreeで分けて、受け入れてから統合する手順【テンプレ付き】」

同じリポジトリ（コードと変更の記録をまとめた場所）でAIを2つ以上同時に動かすときに、仕事ごとに作業場所を分け、触ってよいファイルを決めて頼み、受け入れてから main に統合して片付けるための一式。

| ファイル | 中身 |
|---|---|
| 順番表.md | 同じファイルを触る仕事に順番を付ける表。決め方と記入例つき |
| 洗い出しプロンプト.md | 仕事ごとに触りそうなファイルを、AIに読むだけで挙げてもらう依頼文 |
| 依頼書.md | AIに渡す依頼書のテンプレと記入例（目的・触ってよいファイル・触らないファイル・完了条件・確かめ方） |
| worktree手順.md | 作る→確かめる→統合する→片付けるの git コマンド。練習用リポジトリの作り方、Claude Code の --worktree、Codex の場合の注意つき |
| 受け入れ確認表.md | 統合する前に1つずつ確かめるチェックリスト |
| check_scope.py | 変更が「触ってよいファイル」の中だけか、未コミット（gitにまだ記録していない変更）が残っていないか、main へ早送りできるかを一度に見るスクリプト（任意） |

## 順番

1. 順番表.md を書く（触るファイルが分からなければ 洗い出しプロンプト.md）
2. 仕事ごとに 依頼書.md を1枚書く
3. worktree手順.md の 1 で作業場所を作り、その中でAIを起動して依頼書を渡す
4. 終わったら 受け入れ確認表.md（範囲と状態は check_scope.py か git のコマンド3つで見る）
5. worktree手順.md の 3 で統合、4 で片付け

## check_scope.py

```sh
python3 check_scope.py --base main --allow src/sort.py --allow tests/
python3 check_scope.py --base main --allow-file 触ってよいファイル.txt --out ../受け入れ記録_sort.md
python3 check_scope.py -C ../myapp-sort-reverse --base main --allow src/sort.py
```

- 仕事の作業場所（worktree）の中で実行するか、-C でそのフォルダーを指定する。main を開いたフォルダーで実行すると止まる
- 触ってよいファイルは、リポジトリの一番上からの相対パスで書く。`tests/` や `tests` はそのフォルダーの下全部、`src/*.py` のように * も使える
- --allow-file は、1行に1つ書いたテキスト。`#` で始まる行と空行は読まない
- 終了コードは 0 が問題なし、1 が確認の必要な点あり、2 が実行できなかった（指定の誤りなど）
- 次の場合は何も確かめずに 2 で止まる：触ってよいファイルの指定が無い・空、絶対パスや `..` を含む指定、`*` だけの指定（全部を許すので確認にならない）、`[` と `]` の数が合わない指定、存在しない --allow-file、存在しないフォルダーや git の外のフォルダー、存在しない --base、main そのものを開いたフォルダー、既にある --out のファイル、存在しないフォルダーへの --out
- ファイルの書き換え・コミット・統合はしない。--out を付けたときだけ結果を書き、同じ名前があれば書かない
- `.gitignore` で無視されているファイル（ビルドの出力など）は見ない。作業場所の外に書いたもの（メモ、外部サービス）も見ない。そこは受け入れ確認表で自分で見る
- キットのフォルダーはリポジトリの外に置く。リポジトリの中に置くと、キットのファイル自体が「範囲の外」に数えられる。--out の書き出し先も作業場所の外にする

### 動作を確かめた範囲

- macOS 26.6・Python 3.14.6・git 2.50.1 で、一時的に作ったリポジトリを使って試験した（正常系、範囲の外の変更、未コミット、gitに入っていない日本語名と空白入りのファイル、名前の変更、早送りできない場合、detached HEAD、上の「2で止まる」場合のすべて）
- 書き方は Python 3.8 の文法の範囲に収めたが、3.8 での実行は確かめていない
- Windows の実機では確かめていない。Windows では `python3` を `py -3` に置き換える
- 結果が「問題なし」でも、完了条件を満たしたかどうかは見ていない。受け入れ確認表の残りの項目は自分で確かめる

## 気をつけること

- 一時退避（git stash）は、全部の worktree で共有される。ある作業場所で退避したものが、別の作業場所の `git stash list` にも出る。AIには stash をさせない
- worktree が分けるのは、リポジトリの中のファイルだけ。シミュレーターやエミュレーター、ローカルで動かすサーバー、メモアプリ、外部サービスは分かれない。出力先や使う端末は、依頼書で仕事ごとに別にする
