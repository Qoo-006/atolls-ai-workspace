# 依頼書のテンプレ（仕事1つにつき1枚）

AIに仕事を渡すときに、最初のメッセージとしてそのまま貼る。
「触ってよいファイル」は受け入れのときに check_scope.py の --allow にそのまま使うので、リポジトリ（コードと変更の記録をまとめた場所）の一番上からの相対パスで書く。
同時に動かす別の仕事が触っているファイルは「触らないファイル」に名前を挙げる。

## テンプレ

```text
# 依頼書：（仕事の名前）

- 仕事の名前:
- 目的:
- ブランチ名:
- 作業場所: （このフォルダーの外には書かない）
- 起点: main
- 触ってよいファイル:
  -
- 触らないファイル:
  -
- 出力先（作業場所の外に書くもの）:
- 完了条件:
  -
- 確かめ方:
- やらないこと:
  - main への統合、push、ブランチの削除（受け入れのあとに自分でやる）
  - 強制的な上書き・リセット・一時退避（--force、reset、stash）
  - 触ってよいファイルの外の「ついでの直し」（気づいたら報告に書く）
- 終わったら報告すること:
  - 変えたファイルの一覧と、それぞれ何を変えたか
  - 実行した確認のコマンドと、その結果
  - 未コミット（gitにまだ記録していない）の変更が残っていないか
  - 触ってよいファイルの外を変えたくなった点と、その理由
```

## 記入例

```markdown
# 依頼書：並び替えに逆順を足す

- 仕事の名前: sort-reverse
- 目的: 一覧の並び替えで、新しい順（逆順）も選べるようにする
- ブランチ名: task/sort-reverse
- 作業場所: ../myapp-sort-reverse（このフォルダーの外には書かない）
- 起点: main
- 触ってよいファイル:
  - src/sort.py
  - tests/test_sort.py
- 触らないファイル:
  - src/theme.py（別の仕事 theme-green が変更中）
  - README.md と設定ファイル
- 出力先（作業場所の外に書くもの）: なし
- 完了条件:
  - sort_items に reverse=True を渡すと逆順で返る
  - 前からあるテストと、足したテストが全部通る
- 確かめ方: 作業場所の中で python3 -m pytest tests/ を実行する
- やらないこと:
  - main への統合、push、ブランチの削除（受け入れのあとに自分でやる）
  - 強制的な上書き・リセット・一時退避（--force、reset、stash）
  - 触ってよいファイルの外の「ついでの直し」（気づいたら報告に書く）
- 終わったら報告すること:
  - 変えたファイルの一覧と、それぞれ何を変えたか
  - 実行した確認のコマンドと、その結果
  - 未コミットの変更が残っていないか
  - 触ってよいファイルの外を変えたくなった点と、その理由
```
