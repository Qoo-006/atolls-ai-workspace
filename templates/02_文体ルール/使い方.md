# 文体ルールの使い方

対応する記事：「自分の文体ルールを過去の文章から作って、AIの下書きを媒体ごとに検査する手順【テンプレ付き】」

| ファイル | 中身 |
|---|---|
| 文体プロファイル.md | AIに読ませる文体のルールと、検査の規則を1つにまとめたテンプレ。記入例入り |
| style_check.py | プロファイルの「## 規則：」の節で原稿を1行ずつ見る道具。初稿と仕上げの差分も出せる |
| 抽出プロンプト.md | 自分の過去の文章から、プロファイルの下書きをAIに作らせる依頼文 |
| 直し依頼.md | 検査で当たった行だけをAIに直させる依頼文 |

## コマンド

Windows では `python3` を `py -3` に置き換える。

```sh
python3 style_check.py check 文体プロファイル.md 原稿.md --media note
python3 style_check.py diff 初稿.md 仕上げ.md
```

- 終了コード 0：規則に当たる行がない
- 終了コード 1：規則に当たる行がある（行番号つきで出る）
- 終了コード 2：止めた（ファイルがない、フォルダーを渡した、UTF-8で読めない、規則の書き方が違う、正規表現が壊れている、指定した媒体の節がない、規則が1件もない、本文が空、コードブロックや先頭のプロパティが閉じていない）

見ないのは、先頭のプロパティ（--- で囲んだ範囲）、コードブロック、` で囲んだコード、URL、引用（> で始まる行）、HTMLのコメント。
style_check.py はファイルを読むだけで、書き換えない。

## 規則の書き方

プロファイルの「## 規則：共通」は全部の媒体に、「## 規則：note, x」のように書いた節はその媒体にだけ当てる。
1行に1つ、「- 規則名: 値」の形で書く。

| 規則名 | 値の例 | 当たるもの |
|---|---|---|
| 使わない | シームレス | その文字が入った行 |
| 使わない形 | と言え(る\|ます)(でしょう\|だろう) | 正規表現に当たる行 |
| 使わない記号 | 句点 | 句点・読点・感嘆符・疑問符・三点リーダー・絵文字を名前で書く。全角と半角をまとめて見る |
| 文末に置かない | です | その形で終わる文 |
| 同じ文末の連続 | 3 | 最後の2文字が同じ文が、その数だけ続いたところ（箇条書きは数えない） |
| 1文の最大字数 | 70 | それより長い文（空白は数えない） |
| 全体の最大字数 | 140 | 原稿全体の字数（空白とURLは数えない） |
| 回数の上限 | さらに 2 | 原稿全体でその回数を超えた言い回し |

数字の規則（同じ文末の連続・1文の最大字数・全体の最大字数・回数の上限）は、媒体の節に書いた値が「共通」の値より優先される。

## 動作を確かめた範囲

- 2026-10-18 に macOS 26.6.2、Python 3.14.6 と Python 3.9.6 で確認した
- 確かめたこと：note・X・LinkedInの3媒体の切り替え、該当あり・なしの終了コード、媒体の節の数字が共通の値より優先されること、箇条書きを同じ文末の連続に数えないこと、BOM付きと改行がCRLFの原稿、差分の表示、異常系（ファイルがない、フォルダーを渡した、UTF-8以外の原稿、壊れた正規表現、知らない規則名・記号名、数字でない値、形の違う規則行、存在しない媒体、規則0件、本文が空、閉じていないコードブロックと先頭のプロパティ）で終了コード2になること、実行の前後で入力ファイルが変わらないこと
- Windows は未確認

検証済みの完成品ではなく、自分の規則に合わせて直しながら使う前提の道具として配っている。

## 置き場所の注意

samples/ や feedback.md には、自分の文章や仕事の場面が入る。公開するフォルダーやGitの管理には入れない。
